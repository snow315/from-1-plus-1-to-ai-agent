# LAB-0001 — 计算机凭什么知道 `1+1=2`？

## 实验定位

本实验把一次加法拆成三个可观察环节：**表示数字 → 按规则变换状态 → 解释结果**。

- 必要性：**主链必须**。如果不理解“表示 + 规则 + 执行”如何产生计算结果，后面很容易把神经网络、Transformer 或 Agent 当成会魔法的黑箱。
- 直接前置：会运行一个 Python 文件，并能读懂字符串和 `while` 循环。
- 直接后续：同一组简单规则为什么能处理不止一个输入，以及规则怎样进一步变成逻辑门和机器指令。

## 核心问题与因果链

**核心问题：计算机凭什么得到 `1+1=2`，而不是别的结果？**

`把 1 表示成一根计数棒 |` → `给定“每次把右边一根棒移到左边”的规则` → `规则重复执行，直到右边为空` → `左边出现两根棒 ||` → `按约定把两根棒解释成 2` → **结果来自表示、规则和机械执行的组合，而不是计算机自己理解了“2”**

## 实验边界

本实验负责证明：

- 数字必须先有机器可操作的表示；
- 一条局部规则可以重复组合成完整计算；
- 换掉规则，即使输入和执行器不变，结果也会改变。

本实验不负责解释真实 CPU 的晶体管、二进制加法器或 Python 解释器内部实现。这里使用“计数棒”表示，是为了让因果过程完全可见。

暂不展开：二进制、布尔代数、逻辑门、形式化证明，以及“知道”和“理解”的哲学定义。

## 最低前置知识

- 字符串 `"|"` 表示一根计数棒，`"||"` 表示两根；
- 空字符串 `""` 表示零根；
- 循环会重复执行同一条规则，直到条件不成立。

## 假设与变量

**假设：**如果加法结果由表示和状态转换规则决定，那么在输入保持为 `| + |` 时：

- 使用“移动”规则，应观察到 `| + | → || + 空`，解码结果为 `2`；
- 改用“丢弃”规则，应观察到 `| + | → | + 空`，解码结果为 `1`；
- 因为两次实验只有规则不同，结果差异可以归因于规则，而不是输入。

改变的是规则；观察的是每一步状态和最终计数；保持不变的是输入、停止条件和结果读取方式。

## 最小实验

工具：Python 3，仅使用标准语法，不需要安装第三方库。

运行：

```powershell
python .\LAB-0001\experiment.py
```

脚本把状态写成 `(left, right)`：正常规则每一步从 `right` 取一根棒，放到 `left`；反事实规则则把取出的棒丢掉。

## 操作手顺与运行前预测

1. 先不要运行，手写正常规则的下一状态：`("|", "|") → ("||", "")`。
2. 预测正常规则输出的数字应为 `2`。
3. 预测丢弃规则输出的数字应为 `1`。
4. 运行脚本，对照终端中的逐步状态。
5. 在代码末尾把第二个输入从 `"|"` 改为 `"||"`；正常规则应多执行一步并得到 `3`，丢弃规则仍得到 `1`。

## 期待结果与原因

```text
Input: | + |

[correct rule: move]
step 0: | + |
step 1: || + (empty)
decoded result: 2

[counterfactual rule: discard]
step 0: | + |
step 1: | + (empty)
decoded result: 1
```

正常规则保留了两根输入棒，只改变它们的位置，所以最终有两根；错误规则破坏了“总棒数不变”这个条件，所以只剩一根。循环本身并不知道加法：它只是忠实执行被提供的状态转换。

## 验收条件

完成实验时，你应能不用背代码，说明并验证：

1. 为什么输入 `| + |` 在移动规则下必然结束于 `|| + 空`；
2. 为什么只改规则会让同一输入得到不同结果；
3. `2` 从哪里来：它是对最终两根计数棒的解码，不是机器凭空知道的事实；
4. 回答原问题：**计算机并非先“知道” `1+1=2`，而是我们规定表示和规则，执行器机械地应用规则；这些规则保持了加法所需的关系，因此结果被解码为 2。**

## 完成后必须理解

- 计算至少包含三层：数据的表示、允许的变换规则、规则的执行。
- 复杂计算可以由局部规则反复组合而成；本实验中的“一次移动”就是最小例子。
